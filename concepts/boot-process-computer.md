# Computer Boot/Bootstrap Process

- The bootstrap process (or booting) is the sequence of operations that a computer performs automatically after it is powered on, to load the operating system kernel into memory and start it.
- Goal is to initialize hardware, locate bootable media, load and run the OS kernel.

- | Stage No. | Stage / Component                                                | Purpose                          | Description                                                                                                            | Output / Result                                      |
  | --------- | ---------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
  | **1**     | **`Power ON`**                                                   | Start hardware operation.        | User presses the power button; power is supplied to all components and the CPU begins executing the first instruction. | System hardware receives power and starts execution. |
  | **2**     | **`CMOS & CMOS Battery Activation`**                             | Maintain BIOS/UEFI settings.     | CMOS holds system(BIOS/UEFI) configuration; the CMOS battery preserves it even when the PC is off.                     | BIOS configuration retained and available.           |
  | **3**     | **`Firmware Initialization (BIOS/UEFI)`**                        | Initialize and test hardware.    | BIOS/UEFI firmware initializes CPU, memory, and devices, preparing the system for startup.                             | Basic hardware initialized.                          |
  | **4**     | **`POST (Power-On Self-Test)`**                                  | Verify hardware functionality.   | BIOS/UEFI runs diagnostic checks on RAM, CPU, keyboard, and storage devices.                                           | Hardware verified and functioning.                   |
  | **5**     | **`Read CMOS Settings`**                                         | Load system configuration.       | BIOS reads boot order, date/time, and hardware preferences from CMOS memory.                                           | System configuration applied.                        |
  | **6**     | **`Detect Bootable Device`**                                     | Identify OS boot source.         | BIOS/UEFI scans available storage devices (HDD, SSD, USB, etc.) in defined boot order.                                 | Bootable device detected.                            |
  | **7**     | **`Load Boot Sector / MBR (Legacy) or EFI Boot Manager (UEFI)`** | Transfer control to bootloader.  | BIOS loads the MBR (for legacy) or EFI Boot Manager (for UEFI) which points to the bootloader (e.g., GRUB).            | Bootloader located and loaded into memory.           |
  | **8**     | **`Execute Bootloader (GRUB / LILO / Bootmgr)`**                 | Load kernel and initramfs.       | Bootloader loads the Linux kernel and initramfs into RAM and passes kernel boot parameters.                            | Kernel and initramfs ready in memory.                |
  | **9**     | **`Kernel Initialization`**                                      | Initialize core OS components.   | The kernel decompresses, initializes CPU, memory, and drivers, and mounts a temporary root filesystem (initramfs).     | Kernel running; temporary FS mounted.                |
  | **10**    | **`Mount Root Filesystem`**                                      | Access the real root filesystem. | initramfs scripts detect and mount the actual root (/) filesystem, then switch from temporary to permanent root.       | Real root filesystem mounted.                        |
  | **11**    | **`Start Init Process (systemd)`**                               | Begin user-space initialization. | Kernel executes systemd (PID 1), which manages system startup and service initialization.                              | systemd started; user-space active.                  |
  | **12**    | **`Systemd Targets (Runlevels)`**                                | Define operating mode.           | systemd activates the configured target, such as `multi-user.target` (CLI) or `graphical.target` (GUI).                | System reaches chosen target mode.                   |
  | **13**    | **`Display Manager or getty Starts`**                            | Provide login interface.         | systemd starts getty (text login) or Display Manager (GUI login like GDM/LightDM).                                     | Login prompt or GUI login displayed.                 |
  | **14**    | **`User Authentication & Session Start`**                        | Verify user and start session.   | Credentials verified via PAM; on success, the user’s shell or desktop environment launches.                            | User logged in; system ready for use                 |
